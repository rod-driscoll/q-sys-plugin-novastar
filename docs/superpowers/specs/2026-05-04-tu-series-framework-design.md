### Build workflow

1. Edit source files (primarily `runtime.lua` for logic, `controls.lua` / `layout.lua` for UI changes).
2. Run VS Code build task `Ctrl+Shift+B` → prompts for version increment (ver_dev / ver_fix / ver_min / ver_maj).
3. `compile_plugin.sh` increments version in `info.lua`, concatenates lua files alphabetically (c→c→i→l→p→r, placing `runtime.lua` last as required) into `plugin.lua`.
4. `PLUGCC.exe {name} plugin.lua` generates `content/novastar.qplug`.
5. `make_dev.sh` and `copy_plugin.cmd` deploy the plugin.

`plugin.lua` is gitignored — it is a generated artefact.

## 3. Protocol — Packet Builder

Both VX/ProHD and TU series use the **same binary packet structure**:

```
[55 AA] [ACK] [Label] [SrcAddr] [DstAddr] [DevType] [Port]
[Board Lo] [Board Hi] [Code] [Reserved]
[Reg0] [Reg1] [Reg2] [Reg3]
[DataLen Lo] [DataLen Hi]
[Data bytes…]
[Checksum Lo] [Checksum Hi]
```

Checksum = sum of all bytes after the `55 AA` header + `0x5555`, stored little-endian.

| Field | VX/ProHD | TU |
|---|---|---|
| Source Address | `0xFE` | `0xFC` |
| TCP Port | 5200 | 5201 |
| All other fields | identical format | identical format |

### Builder (top of `runtime.lua`)

```lua
local VX_SRC, TU_SRC = 0xFE, 0xFC
local READ, WRITE    = 0x00, 0x01

local function buildPacket(label, src, dst, devType, port, boardLo, boardHi, code, reg, dataLen, data)
    local bytes = {0x00, label, src, dst, devType, port, boardLo, boardHi, code, 0x00,
                   reg[1], reg[2], reg[3], reg[4],
                   dataLen & 0xFF, (dataLen >> 8) & 0xFF}
    if data then for _, b in ipairs(data) do table.insert(bytes, b) end end
    local sum = 0x5555
    for _, b in ipairs(bytes) do sum = sum + b end
    local pkt = {0x55, 0xAA}
    for _, b in ipairs(bytes) do table.insert(pkt, b) end
    table.insert(pkt, sum & 0xFF)
    table.insert(pkt, (sum >> 8) & 0xFF)
    return pkt
end

local function sendPacket(pkt)
    if DebugTx then print("Tx: " .. hexDump(pkt)) end
    if socket.IsConnected then
        local s = ""
        for _, b in ipairs(pkt) do s = s .. string.pack("B", b) end
        socket:Write(s)
    end
end
```

### Refactored command tables

Repetitive tables collapse into builder loops. Example — test patterns (currently 9 × 4 = 36 near-identical rows):

```lua
local function makeTestPattern(patternId)
    local cmds, labels = {}, {0xe7, 0xe8, 0xe9, 0xea}
    for i, lbl in ipairs(labels) do
        table.insert(cmds, buildPacket(lbl, VX_SRC, 0x00, 0x01, i-1, 0xFF, 0xFF, WRITE,
                                       {0x01, 0x01, 0x00, 0x02}, 1, {patternId}))
    end
    return cmds
end

local TestPatterns = {
    RED=makeTestPattern(0x02), GREEN=makeTestPattern(0x03), BLUE=makeTestPattern(0x04),
    WHITE=makeTestPattern(0x05), HORIZ=makeTestPattern(0x06), VERT=makeTestPattern(0x07),
    DIAG=makeTestPattern(0x08), GRAY=makeTestPattern(0x09), AGING=makeTestPattern(0x0A),
}
```

DisplayNormal / DisplayFreeze / DisplayBlack tables are similarly expressed as `buildPacket(...)` calls per model rather than raw byte arrays.

## 5. Controls

All controls defined in `GetControls()` for all models. Runtime logic shows/hides model-specific controls.

### Shared (all models)

| Name | Type | PinStyle | Notes |
|---|---|---|---|
| `IPAddress` | Text | Both | Replaces `IP Address` property — watch EventHandler to reconnect |
| `Model` | ComboBox | Both | Choices: VX4S, VX4S_N, VX6S, VX1000, PROHD, PROUHDJR, MCTRL4K, TU — watch EventHandler to reconfigure |
| `Brightness` | Knob 0–255 | Both | Shared — Receiving Card brightness |
| `Status` | Text (output) | Output | Connection / error status string |

### VX / ProHD / MCTRL4K only

| Name | Type | Notes |
|---|---|---|
| `IN1`–`IN9`, `IN0` | Button/Trigger | 10 input buttons — hidden when model = TU |
| `PRESET1`–`PRESET10` | Button/Trigger | Hidden when model = TU |
| `TEST_RED/GREEN/BLUE/WHITE/HORIZ/VERT/DIAG/GRAY/AGING` | Button/Trigger | Hidden when model = TU |
| `Normal`, `Freeze`, `Black` | Button/Trigger | Display modes — hidden when model = TU |

### TU only

| Name | Type | PinStyle | Notes |
|---|---|---|---|
| `INPUT_ANDROID` | Button/Trigger | Input | Android source — hidden when model ≠ TU |
| `INPUT_HDMI1` | Button/Trigger | Input | HDMI1 source |
| `INPUT_HDMI2` | Button/Trigger | Input | HDMI2 source |
| `INPUT_HDMI3` | Button/Trigger | Input | HDMI3 source |
| `SCREEN_ON` | Button/Trigger | Input | Turn screen on (DevType=0x08, Reg=0x0D, Data=0x01) |
| `SCREEN_OFF` | Button/Trigger | Input | Turn screen off (Data=0x00) |
| `STANDBY` | Button/Trigger | Input | Enter standby (Reg=0x01) |
| `WAKE` | Button/Trigger | Input | Wake from standby (Reg=0x02) |
| `VOLUME` | Knob 0–100 | Both | System volume (Reg=0x06) |
| `MUTE` | Button/Toggle | Both | Value=1 → Mute (Reg=0x05, Data=0x15); Value=0 → Unmute (Data=0x05) |
| `CURRENT_SOURCE` | Text (output) | Output | Readback: Android / HDMI1 / HDMI2 / HDMI3 |
| `SYSTEM_STATUS` | Text (output) | Output | Readback: Standby / Normal display |

## 7. Layout

### Plugin size

Both pages use **420 × 380 px** (floating panel style, matching Samsung reference). This replaces the current 1000 × 120 rack format.

### Setup page

```
y=5   ┌─ Connect ──────────────────────────────────┐  y=5, size {410,110}
      │  IP Address  [IPAddress field            ]  │
      │  Model       [▼ Model combo              ]  │
      │  Port        [auto label: 5200 or 5201   ]  │
      └────────────────────────────────────────────┘
y=125 ┌─ Status ───────────────────────────────────┐  y=125, size {410,150}
      │  [══════════════ Status LED ══════════════] │
      │  System Status   [SYSTEM_STATUS text     ]  │  (TU only row — hidden for VX)
      │  Current Source  [CURRENT_SOURCE text    ]  │  (TU only row — hidden for VX)
      └────────────────────────────────────────────┘
```

Port is a read-only `Text` control updated at runtime when the Model control changes (5200 for VX/ProHD/MCTRL4K, 5201 for TU). Note: the `port` parameter inside `buildPacket()` is the packet-level Port Address field (board ethernet port, 0x00–0xFF) — distinct from the TCP connection port.

### Control page

**VX / ProHD layout** (existing rack-style preserved, re-expressed as positioned controls inside the 420 × 380 panel):
- Row 1: Input buttons IN1–IN10 + Brightness knob + Mode buttons (Normal/Freeze/Black)
- Row 2: Test pattern buttons
- Row 3: Preset buttons

**TU layout** (shown at runtime when Model = TU, VX controls hidden):
- Row 1: Source buttons (ANDROID / HDMI1 / HDMI2 / HDMI3) + CURRENT_SOURCE readback
- Row 2: SCREEN_ON / SCREEN_OFF / STANDBY / WAKE buttons
- Row 3: VOLUME knob + MUTE button + Brightness knob
- Row 4: SYSTEM_STATUS readback

Controls for the non-active model are set `IsInvisible = true` and `IsDisabled = true` in the `if Controls then` block at startup and whenever the Model control changes.

## 8. Runtime Behaviour

### Connection

```lua
local port = (Controls["Model"].String == "TU") and 5201 or 5200

Controls["IPAddress"].EventHandler = function()
    socket:Disconnect()
    socket:Connect(Controls["IPAddress"].String, port)
end

Controls["Model"].EventHandler = function()
    applyModelLayout()   -- show/hide controls
    port = (Controls["Model"].String == "TU") and 5201 or 5200
    socket:Disconnect()
    if Controls["IPAddress"].String ~= "" then
        socket:Connect(Controls["IPAddress"].String, port)
    end
end
```

### TU status polling

After connect, poll on a `Timer` every 5 seconds:
- Current Display Source: DevType=0x06, Reg=0x04, Code=READ → update `CURRENT_SOURCE.String`
- System Status: DevType=0x06, Reg=0x0D, Code=READ → update `SYSTEM_STATUS.String`

### TU command register map (Android Card Control, DevType=0x08)

| Action | Reg | Data |
|---|---|---|
| Standby | `{0x01,0x00,0x00,0x00}` | — |
| Wake | `{0x02,0x00,0x00,0x00}` | — |
| Switch source | `{0x04,0x00,0x00,0x00}` | 0x01=HDMI1, 0x02=HDMI2, 0x03=Android, 0x04=HDMI3 |
| Mute | `{0x05,0x00,0x00,0x00}` | 0x15=mute, 0x05=unmute |
| Volume | `{0x06,0x00,0x00,0x00}` | 0x00–0x64 |
| Screen | `{0x0D,0x00,0x00,0x00}` | 0x01=on, 0x00=off |

Exact byte sequences to be verified against hardware during implementation — the register addresses are derived from the TU Series Control Protocol V3.0.0 document in the repo root.

## 9. Debug Logging

Property: `Debug Print` enum — None / Tx/Rx / Tx / Rx / Function Calls / All

```lua
local DebugTx, DebugRx, DebugFunction = false, false, false
local DebugPrint = Properties["Debug Print"].Value

local function SetupDebugPrint()
    if     DebugPrint == "Tx/Rx"          then DebugTx,DebugRx = true,true
    elseif DebugPrint == "Tx"             then DebugTx = true
    elseif DebugPrint == "Rx"             then DebugRx = true
    elseif DebugPrint == "Function Calls" then DebugFunction = true
    elseif DebugPrint == "All"            then DebugTx,DebugRx,DebugFunction = true,true,true
    end
end
```

Applied at every `print()` site:

| Site | Guard |
|---|---|
| Every function entry point | `DebugFunction` |
| `sendPacket()` | `DebugTx` — prints hex dump of outgoing bytes |
| `socket.Data` handler | `DebugRx` — prints hex dump of received bytes |
| Checksum / parse errors | `DebugRx` |
| Connect / disconnect / error events | `DebugFunction` |

`hexDump()` (renamed from existing `hex_dump()`) is the shared byte printer used by Tx/Rx logging.
